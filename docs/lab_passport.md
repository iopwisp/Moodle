# Паспорт учебного стенда

Паспорт связывает конкретный workspace с целью лабораторной, описанием принадлежности стенда,
цитатой из инструкции, точными адресами и перечнем capabilities. Это записанный контекст,
а не независимое подтверждение разрешения и не способ отключить ограничения AI или policy.

Сначала подготовьте workspace командой `assignment`. Затем создайте паспорт по реальной
инструкции, например:

```powershell
py -3.12 -m lab_agent.cli lab-passport <workspace> --create `
  --name "Web security lab" --purpose "Inspect the supplied lab website" `
  --owner "University-provided training environment" `
  --source input/instruction.txt `
  --excerpt "Use only lab.local in this authorized university exercise." `
  --target lab.local --action browser.visit `
  --restriction "No external systems"
```

Это пример формата: источник, цитату, описание стенда и адрес нужно заменить настоящими
данными задания. Цитата должна буквально находиться в источнике. Файл должен быть внутри
workspace; для PDF/DOCX используется штатное извлечение текста из самого файла и проверяется
хеш скопированного источника. Если существенный текст доступен только на изображении, сначала
прочитайте его соответствующим инструментом и сохраните отдельную текстовую заметку с
ссылкой на страницу; паспорт указывает на эту заметку, а не выдаёт её за прямое извлечение PDF.
Секреты и пароли в паспорт добавлять нельзя.

`--target`, `--action`, `--restriction` можно повторять. Цели — точные IP/имена хостов без
портов, URL-путей, CIDR и wildcard. Список capabilities проверяется по реестру. Описание
принадлежности стенда берётся из известных сведений; владение чужим сервером не предполагается.

```powershell
py -3.12 -m lab_agent.cli lab-passport <workspace>
py -3.12 -m lab_agent.cli context <workspace>
```

Полный документ находится в `metadata/lab_passport.json`. `context` включает краткий
`lab_scope` с цитатой и списками целей/действий. Сохраняется SHA-256 источника. Существующий
паспорт не перезаписывается без явного `--create --replace` и повторной проверки цитаты.

## Что проверяется при выполнении

- В runner и при `do` через реестр проверяются заявленные сетевые capabilities и операции
  с распознанными полями адреса (`url`, `target_url`, `target`, `host` и другими из policy).
- Операция должна быть в списке действий, а все явно указанные цели — в паспорте.
  Для сетевой операции без явного адреса требуется указать его в параметрах.
- Разрешение policy требуется отдельно: паспорт не добавляет цели в config и не отменяет
  подтверждения. Для hostname из примера также нужен явный разрешённый стенд в policy.
- Политика браузерной сессии учитывает паспорт при проверке адресов навигации и редиректов.
- Если паспорт испорчен или источник изменён, сетевой шаг блокируется; локальная обработка
  файлов остаётся доступной. Другие независимые шаги может продолжить обычный runner.
- В workspace без паспорта сохраняется прежнее поведение policy.

Это проверка на уровне приложения, не сетевой firewall: она не анализирует произвольный
shell-код, адреса внутри файлов/скриптов, DNS rebinding или сетевые действия стороннего
процесса. Для `kali.run` поле `host` обозначает SSH-подключение, а не все адреса команд
внутри VM. Такие команды отдельно проверяются по исходному заданию и действующей policy.
Текст `restrictions` — контекст для агента; машина автоматически исполняет ограничения
точных целей и списка операций, а не произвольные предложения на естественном языке.
