# План и приёмка скриншотов

`assignment` создаёт `metadata/screenshot_checklist.json` из требований к скриншотам,
извлечённых из инструкции. Агент сверяет список с полным оригиналом задания и дополняет
ключевыми практическими этапами до выполнения. Текст, находящийся только на изображениях
или в плохо извлечённой таблице PDF, может потребовать ручного добавления.

```json
{
  "version": 1,
  "requirements": [
    {
      "id": "S1",
      "requirement": "Окно программы с результатом проверки до изменения настройки",
      "minimum": 1,
      "evidence_ids": []
    },
    {
      "id": "S2",
      "requirement": "Окно программы с результатом повторной проверки после изменения",
      "minimum": 1,
      "evidence_ids": []
    }
  ]
}
```

Это пример структуры, не готовое доказательство. Агент сам заполняет checklist и привязывает
реальные изображения; пользователю не нужно вручную редактировать JSON. `minimum` задаётся
по заданию, а разные состояния лучше разделять на отдельные пункты. Явное требование
«3 скриншота» нужно разбить по смыслу либо поставить `minimum: 3`; извлечение текста само
не интерпретирует числительные и не проверяет содержание изображения.

Снимок регистрируется штатным способом: интеграцией, командой `screenshot --window ...`
или `evidence <workspace> <path> --type screenshot --step N`. После визуальной проверки
его id добавляется в `evidence_ids` соответствующего пункта. Также поддерживаются точные
`requirement_refs` у evidence/шага. Для длинных ссылок поддерживается штатное сокращение
до 300 символов. Нельзя связывать изображение с требованием без проверки его содержания.

`review` возвращает `screenshot_coverage` и не показывает `ready: true`, пока обязательные
пункты не покрыты валидными зарегистрированными скриншотами. При отсутствии или удалении
checklist требования из исходного анализа всё равно проверяются. Дубли с одинаковым SHA-256
считаются одним снимком. Обычная картинка типа `image`, повреждённый или изменённый файл
не заменяет screenshot evidence. Некорректный JSON блокирует готовность.

Проверка кода подтверждает целостность и связь, а не читаемость, происхождение кадра или
его присутствие на странице отчёта. Агент отдельно смотрит каждое изображение, использует
реальное окно программы через PrintWindow, добавляет подписи в отчёт и проверяет итоговые
страницы PDF/DOCX. Отсутствующий обязательный скриншот — незавершённая часть задания.
