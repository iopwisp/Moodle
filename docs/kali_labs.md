# Готовые лабораторные сценарии Kali

`kali_labs` использует существующий транспорт `kali.run`: SSH → настоящий
терминал гостя → PrintWindow окна VirtualBox в Windows. Новые возможности
автоматически появляются в реестре после установки проекта из исходников.
Отдельные скрипты в папке каждого задания больше не нужны для этих операций.

## Подготовка

Настройте VM и SSH по [kali.md](kali.md), войдите в графический сеанс Kali.
Окно VirtualBox должно быть открыто и не свёрнуто; при пустом кадре шаг
блокируется. Программы устанавливаются в Kali отдельно: сценарии ничего не
скачивают, не запускают sudo и не создают DVWA/базу данных автоматически.

Сначала создайте workspace из задания:

```powershell
py -3.12 -m lab_agent.cli analyze C:\Labs\assignment.txt
py -3.12 -m lab_agent.cli capabilities --tool kali_labs
```

В дальнейших примерах замените `workspace/MyLab` на путь из результата
`analyze`. Параметры SSH берутся из локальной секции `kali` в `config.yaml`.
В плане действуют обычные подтверждения для `risk=unsafe`.

## Проверка готовности

```powershell
py -3.12 -m lab_agent.cli do workspace/MyLab kali_labs.preflight
```

Получается инвентаризация Nikto, John, Hashcat, RainbowCrack, GVM, ZAP,
Chromium/ChromeDriver и Selenium, наличие NASL-файлов и результат `hashcat -I`.
`verified=true` здесь означает, что проверка окружения выполнена, а не что
все лабораторные готовы. Читайте `details.lab.ready` и `missing_tools`.
Наличие компонентов GVM и feed не доказывает, что сервисы запущены или
сканирование завершилось. Отсутствующие компоненты не подменяются результатами
из методички.

## Nikto

```powershell
py -3.12 -m lab_agent.cli do workspace/MyLab kali_labs.nikto -p url=http://127.0.0.1:8088 -p seconds=60
py -3.12 -m lab_agent.cli do workspace/MyLab kali_labs.nikto -p url=http://127.0.0.1:8088 -p seconds=60 -p sql_only=true
```

Только HTTP с числовым loopback-адресом **внутри Kali**. Удалённые IP,
доменные имена, userinfo и URL с query/fragment отклоняются до SSH. Nikto не
получает флаг следования перенаправлениям, а проверка обновлений выключена.
Результаты TXT/CSV сохраняются в `results/`, включая версии Nikto, которые
добавляют расширение повторно. Ограничение времени: 5–600 секунд.
Ошибки сканирования и достигнутый лимит дают `partial` и `verified=false`.
Сообщения Nikto требуют ручной проверки и не считаются доказанными SQL/XSS.

## Учебные MD5-хеши

Поместите **копию** файла в `input/hashes.txt`: одна строка `MD5` или
`username:MD5`, без заголовка. Максимальный размер — 1 MiB. Исходник не
меняется. Словарь находится в Kali, путь абсолютный; `.gz` распаковывается
в отдельную временную папку без изменения оригинала.

```powershell
py -3.12 -m lab_agent.cli do workspace/MyLab kali_labs.passwords -p hashes=input/hashes.txt -p engine=john
py -3.12 -m lab_agent.cli do workspace/MyLab kali_labs.passwords -p hashes=input/hashes.txt -p engine=hashcat -p seconds=60
```

Используются отдельные pot-файлы задания. Найденные значения повторно
хешируются и сравниваются с входом; одинаковые хеши разных строк учитываются.
Шаг подтверждается только при восстановлении всех входных строк и завершении
проверки результата. Частичный подбор сохраняется с `verified=false`.
Отсутствие вычислительного backend у Hashcat даёт `blocked`; результат John
не выдаётся за результат Hashcat. Локальные evidence содержат раскрытые
учебные пароли — учитывайте это перед передачей файлов.

## DVWA

Нужны существующая локальная DVWA с учебной парой `admin/password`, Selenium,
Chromium и совместимый ChromeDriver **в Kali**. URL может включать префикс
`/dvwa`. Сценарий открывает собственный графический браузер, проверяет DVWA,
выполняет тест и закрывает только свой браузер. Чужие сеансы не закрываются.

```powershell
py -3.12 -m lab_agent.cli do workspace/MyLab kali_labs.dvwa -p url=http://127.0.0.1:8088 -p case=sql
py -3.12 -m lab_agent.cli do workspace/MyLab kali_labs.dvwa -p url=http://127.0.0.1:8088 -p case=reflected_xss -p level=high
```

SQL: только Low, фиксированный читающий запрос `' OR 1=1 #`; сохраняются
реально полученные записи. XSS: Low/Medium/High, фиксированный безвредный
`alert`; проверяется фактический текст диалога. Браузер направляет внешний
трафик в неработающий локальный proxy; разрешён loopback-адрес стенда.
База не сбрасывается. Уровень безопасности меняется только в созданной
тестовой сессии. Никакие cookies не отправляются наружу.

Скриншот этой версии показывает **терминал с наблюдённым результатом** после
закрытия браузера. Это не снимок всплывающего окна XSS. Stored XSS, SQL
извлечение паролей, установка стенда, GVM/ZAP и RainbowCrack пока не добавлены
как готовые сценарии; для них остаётся общий `kali.run` и ручная проверка.

## Evidence, повтор и отчёт

У каждого шага есть JSON с фактическим статусом, вывод программы, экспорты
и настоящий снимок окна. Evidence регистрируются с SHA-256. Если SSH,
терминал или PrintWindow не подтвердились, шаг не становится завершённым,
даже когда программа внутри гостя успела отработать.

`-p execution_id=step-one` позволяет восстановить evidence без повторного
запуска. Для нового опыта задайте новый ID. При неизвестном исходе SSH
сначала проверьте гостя — автоматического повторного выполнения нет.

Для отчёта используйте существующий `report.md` и реальные файлы из
`results/`/`screenshots/`; формулировки и ответы задания заполняются по
наблюдениям. Автоматическое сочинение ответов этими командами не выполняется.

```powershell
py -3.12 -m lab_agent.cli lint-report workspace/MyLab/report.md
py -3.12 -m lab_agent.cli build-report workspace/MyLab/report.md
```

Этот генератор уже создаёт DOCX и PDF; прикладывайте нужный формат по
требованиям преподавателя. Отдельный генератор PDF для каждого задания
не требуется.
