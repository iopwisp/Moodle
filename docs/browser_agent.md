# Браузерный агент

`browser.run_task` выполняет целое задание в одной сессии Chromium:
читает страницу, передаёт модели видимые элементы, выполняет одно действие
и заново проверяет страницу. Скрипт для каждого сайта не требуется.
Подходит для обычных HTML-форм и учебных сайтов; сложные canvas-интерфейсы
и нестандартные редакторы могут потребовать отдельной интеграции.

## Запуск с локальным Qwen3

Для первой пробы есть локальный стенд с двумя вариантами формы. Скрипт сам
поднимает сервер на loopback, запускает настоящую модель и Chromium,
сохраняет доказательства в `workspace/BrowserAgentDemo/` и закрывает свои процессы:

```powershell
py -3.12 scripts/browser_agent_demo.py
# либо через настроенный Codex CLI:
py -3.12 scripts/browser_agent_demo.py --provider codex
```

Демонстрация не меняет ваш `config.yaml`. Она использует локальный `qwen3:4b`
по умолчанию и требует установленного Ollama и Windows с открытым рабочим столом.

Нужны Windows, зависимости `.[all]`, Chromium (`python -m playwright install chromium`)
и работающий Ollama с установленной моделью. `ollama list` показывает точное имя.
В локальном `config.yaml`:

```yaml
ai:
  provider: ollama
  model: qwen3:4b
  base_url: http://127.0.0.1:11434
  timeout_seconds: 90
  max_retries: 0
  ollama_think: false
  ollama_num_ctx: 16384
browser:
  headless: false
```

Если `config.yaml` уже заполнен, измените только нужные поля, сохранив
остальные настройки. `ollama_think` управляет параметром `think`
[Ollama Chat API](https://docs.ollama.com/api/chat).
Другие настроенные провайдеры также поддерживаются; автоматического
перехода к другому провайдеру или к подготовленной последовательности действий нет.
Большой контекст увеличивает расход памяти Ollama. На машине с небольшим
объёмом VRAM можно уменьшить его до 8192; длинная страница при этом может
потребовать более сильной модели или сокращения задания.

Пример для своего локального стенда (укажите его настоящий адрес и задание):

```powershell
lab-agent do .\workspace\BrowserLab browser.run_task `
  -p url=http://127.0.0.1:8000 `
  -p 'goal=Открой раздел упражнений, выбери сетевую лабораторную и выполни её по условию' `
  -p 'expected_text=Lab completed successfully' `
  -p max_steps=20
```

Можно передать `provider=ollama` и `model=qwen3:4b` параметрами конкретного
запуска. Папка workspace должна быть отдельной для задания.
Действие также доступно планировщику через реестр capabilities и web-панель.

## Результат и скриншоты

Нужен хотя бы один заданный человеком признак результата: `expected_text`
(видимый текст) или `success_selector` (видимый элемент CSS/Playwright).
Если переданы оба, должны выполниться оба. Выбирайте конкретный признак
завершения, например баннер проверенного сервером результата.
Он проверяется программой; ответ модели не считается доказательством.

Перед действиями и при финальной проверке сохраняются реальные снимки
окна Chromium в Windows через `PrintWindow`, с рамкой браузера.
Сворачивать окно нельзя; перекрывать другим окном можно, если Chromium
продолжает отдавать изображение. Если окно не отрисовалось, выполнение
останавливается с причиной. Подмена снимком рабочего стола отсутствует.
Headless и Linux для **этого действия** пока не поддерживаются.
Обычные действия `browser.navigate/click/...` доступны как прежде.

Действия идут через Playwright без системных нажатий клавиш и перемещения
мыши. Браузер открывает своё окно; переключение вкладки может менять его
активность. Это не отдельный виртуальный рабочий стол Windows.

В `results/browser_task_*.json` записываются наблюдения и действия;
в `screenshots/` — снимки, в журнале — их SHA-256.
Неудача, лимит действий, ошибка модели или необходимость входа не
превращаются в успешный результат. При запуске через CLI доказательства
попадают в обычный реестр evidence.

## Ограничения и доступ

- Только localhost или хосты из `policy.network.authorized_targets`.
  При работе этого цикла внешние ресурсы также требуют разрешения;
  добавьте нужные домены учебного стенда и его CDN явно.
- Модель выбирает наблюдённый элемент, действие и значение. Она не может
  выполнять JavaScript, shell-команды или сама расширять список хостов.
  Поддерживаются клик, заполнение, select, checkbox/radio, прокрутка,
  ожидание, переключение разрешённых вкладок и элементы внутри разрешённых iframe.
- Текст страницы считается данными. Он передаётся модели с инструкцией
  игнорировать встроенные команды; это снижает риск prompt injection,
  но не делает выбор модели безошибочным. Используйте отдельную сессию
  учебного стенда, где действия соответствуют вашему заданию.
- Для пароля передайте `secret_names` со списком разрешённых имён переменных
  окружения или записей OS keyring, например `-p 'secret_names=["LAB_PASSWORD"]'`.
  Модель видит имя переменной, значение подставляется локально.
  CAPTCHA/2FA и недостающие данные требуют участия человека.
- Каждая задача ограничена `max_steps` (1–60, по умолчанию 20) и временем
  шага `execution.step_timeout_seconds`. HTTP-вызов модели ограничен
  `ai.timeout_seconds`; после Stop новое действие не выполняется.
- После любого начавшегося запуска автоматическое повторение той же задачи
  заблокировано: отправленная форма могла уже сработать. Сначала прочитайте
  журнал и проверьте состояние стенда, затем для намеренного нового запуска
  добавьте другой `execution_id`. Это относится и к повторному `resume`.

При выборе облачного провайдера текст страниц будет передаваться ему.
С Ollama на `127.0.0.1` решения принимает локальная модель.
